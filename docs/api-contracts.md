## 5. Shared-file rules and PR slices

- TV1 owns `docs/api-conventions.md`, this index and shared auth/error contract coordination. Each module owner implements against the agreed file and proposes changes through a small PR; do not fork endpoint names, error envelope or role middleware.
- Routes are mounted by TV1 after owner PR is reviewed. Changes to `backend/src/app.ts`, frontend router, shared API client, root scripts, schema/migrations/GRANT require explicit affected-module review.
- Any schema mismatch is a separate schema/migration PR. Do not apply a database change from a documentation PR; do not edit initial migration. Data safety and test DB isolation are mandatory.
- PR plan: (1) resolve Ch4↔main schema gap; (2) TV1 auth/RBAC foundation; (3) TV2 auth UI/profile/users; (4) TV3 categories Skill/Admin, guidance and recommendations; (5) TV1 Admin opportunity review; (6) TV4 events/reminders/notifications and dashboard; (7) TV5 forum/moderation with TV4 notification + shared logs; (8) integrated end-to-end review. Each is a proposal sequence; do not mark started/approved until commits/PR prove it.

## 6. Handoff checklist

Before a module implementation starts: (1) owner reads its contract and Ch3/Ch4 source references; (2) verify dependent endpoint/code and current DB migration status; (3) list unresolved decision blockers; (4) agree paths, schema, role, validation, errors and transaction with TV1; (5) use branch from latest origin/main and isolate test DB; (6) test public, role and ownership boundaries; (7) update implementation state with commit/test evidence; (8) cross-module review of auth, categories, deadlines, logs and notifications. No member should re-author a competing contract or claim approval on behalf of another member.

## 7. Quyết định và review còn mở

## 2. Phạm vi dùng chung và vai trò

- **Guest:** request không có phiên UniHub hợp lệ. Đây là trạng thái truy cập, không phải hàng `users` hoặc giá trị `users.role`.
- **Student/Admin:** tài khoản trong DB với `users.role` tương ứng. Mọi quyết định quyền lấy từ bản ghi hiện tại trên server; claim do browser gửi hoặc role trong dữ liệu UI không có thẩm quyền.
- **Admin:** mọi route quản trị, gồm `/api/admin/*`, phải chạy middleware xác thực rồi kiểm tra role Admin tại backend. Frontend route guard chỉ phục vụ điều hướng.
- Nếu một chức năng chỉ dành cho Student, Admin không tự động được phép dùng chức năng đó; Chương 3 BR-08.1/BR-09.1 cấm Admin đăng bài hoặc bình luận diễn đàn. Quyền từng module vẫn phải khớp ma trận Chương 3. Không suy ra quy tắc ownership chỉ từ role.
- Không có password login hoặc local password trong phạm vi này.
- Không thu thập thêm số điện thoại, số định danh cá nhân/CCCD hoặc địa chỉ cư trú chi tiết (Chương 3 NFR-02.2); chỉ dùng claims đã xác minh và dữ liệu tài khoản cần thiết theo schema.

## 3. Dữ liệu và hợp đồng cần giải quyết trước khi code

Schema Prisma hiện tại của `users` có `user_id`, `email` (UNIQUE), `full_name`, `avatar_url`, `role` (`Student`/`Admin`), `major_id`, `academic_year`, `career_goal`, `created_at`, `updated_at`. Không có `google_sub`, cờ trạng thái/khóa, session, refresh token hoặc danh sách thu hồi. Vì vậy schema hiện tại **không thể** thực hiện an toàn liên kết Google ổn định, khóa tài khoản, refresh rotation hay thu hồi phiên.

### Đề xuất schema tối thiểu để review (chưa áp dụng)

1. `users.google_sub VARCHAR(255) NULL UNIQUE` với collation/so sánh case-sensitive (ví dụ `utf8mb4_0900_as_cs`): định danh Google ổn định. Cho phép NULL cho bản ghi cũ chưa được đối soát; luồng đăng nhập không tự nhận bản ghi NULL qua email. Sau migration, tài khoản mới phải được tạo cùng `google_sub`.
2. `users.account_status VARCHAR(10) NOT NULL DEFAULT 'Active'` với CHECK so sánh chính xác, chỉ nhận `Active`/`Locked`.
3. Bảng `auth_sessions` riêng, khóa tới `users.user_id`, session ID ngẫu nhiên, hash refresh verifier, `expires_at`, `revoked_at`, `created_at`/`updated_at`. Không lưu refresh token thô. Chốt chi tiết cột/FK/index/GRANT bằng migration review sau khi nhóm duyệt phương án.

Không suy luận `google_sub` hoặc trạng thái tài khoản cho dữ liệu cũ. Quy trình gắn danh tính cũ phải có đối soát riêng; migration không tự backfill theo email. Việc thêm các trường này sẽ cần sửa Chương 4 §4.3.2.1, `backend/prisma/schema.prisma`, migration mới, database runtime grants và tài liệu API; **không sửa initial migration đã áp dụng**.

## 4. Quy ước lỗi chung cho API auth

Giữ envelope hiện có: `{"error":{"code":"...","message":"..."}}`; không trả token, Google claims thô, SQL, URL kết nối, stack hoặc chi tiết chữ ký. Các mã auth dưới đây là **đề xuất contract**, cần được duyệt; lỗi database dùng `503 SERVICE_UNAVAILABLE`, lỗi bất ngờ dùng `500 INTERNAL_ERROR` theo quy ước chung.

| HTTP | Code đề xuất            | Khi nào                                                                                                                         |
| ---- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 400  | `INVALID_REQUEST`       | JSON sai shape, field thiếu/thừa hoặc token rỗng/sai kiểu.                                                                      |
| 401  | `UNAUTHORIZED`          | Thiếu/sai/hết hạn JWT UniHub hoặc refresh credential không hợp lệ.                                                              |
| 401  | `GOOGLE_TOKEN_INVALID`  | Google ID token sai chữ ký, issuer/audience/expiry hoặc claim bắt buộc không đạt; message không tiết lộ cách xác minh thất bại. |
| 403  | `FORBIDDEN`             | Đã xác thực và có tài khoản Active nhưng role không đủ.                                                                         |
| 403  | `ACCOUNT_DISABLED`      | Google identity hợp lệ nhưng account bị Locked. Không phát token.                                                               |
| 403  | `ACCOUNT_NOT_ALLOWED`   | Nhóm chốt allowlist/domain hoặc policy khác và danh tính không đáp ứng. Không tiết lộ rule nội bộ.                              |
| 409  | `ACCOUNT_LINK_REQUIRED` | Email đã có trên bản ghi chưa liên kết hoặc liên kết xung đột; không trả email/chi tiết bản ghi và không tự gắn.                |

Không trả 401 cho lỗi DB: database outage là lỗi dịch vụ, không phải bằng chứng người dùng đã đăng xuất. 401 nghĩa là chưa có credential phiên hợp lệ; 403 nghĩa là danh tính/phiên hợp lệ nhưng không được phép thực hiện hành động.

## 5. API đề xuất

### 5.1. Đăng nhập/đăng ký Google — `POST /api/auth/google`

| Thuộc tính          | Hợp đồng đề xuất                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Quyền               | Public/Guest; không yêu cầu JWT UniHub. Endpoint này không nhận hoặc tin role từ browser.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Request             | JSON `{ "idToken": "<Google ID token>" }`. Chỉ nhận field này; giới hạn body theo giới hạn JSON API hiện hành. Không nhận email, Google `sub`, `role`, tên/avatar làm bằng chứng danh tính. Kiểm tra `Origin` theo allowlist vì endpoint tạo cookie phiên.                                                                                                                                                                                                                                                  |
| Validation          | Kiểm tra kiểu/không rỗng; xác minh chữ ký với Google keys, `iss`, `aud` bằng backend `GOOGLE_CLIENT_ID`, `exp`, `sub`, `email`, `email_verified === true`. Nếu client dùng nonce thì đối chiếu nonce với challenge. Không dùng decode JWT đơn thuần. Không áp domain allowlist trước khi nhóm chốt.                                                                                                                                                                                                         |
| Thành công          | HTTP 200; `{ "accessToken": "…", "tokenType": "Bearer", "expiresIn": 900, "user": {"id": 12, "email": "…", "fullName": "…", "avatarUrl": null, "role": "Student"} }`; đồng thời set refresh cookie opaque và `Cache-Control: no-store`. Cấu trúc minh họa, không phải dữ liệu thật.                                                                                                                                                                                                                         |
| Lỗi                 | 400 `INVALID_REQUEST`; 401 `GOOGLE_TOKEN_INVALID`; 403 `ACCOUNT_DISABLED`, `ACCOUNT_NOT_ALLOWED` hoặc `FORBIDDEN` nếu Origin không được phép; 409 `ACCOUNT_LINK_REQUIRED`; 503 `SERVICE_UNAVAILABLE`.                                                                                                                                                                                                                                                                                                       |
| Frontend            | Nhận credential từ GIS, gửi nguyên ID token qua HTTPS, không tự gán role. Chỉ khi thành công mới giữ access token trong memory và tải `/api/auth/me`; lỗi không giữ phiên cũ hoặc token Google làm token UniHub.                                                                                                                                                                                                                                                                                            |
| Dữ liệu/transaction | Xác minh với Google ngoài transaction DB. Sau đó transaction ngắn: tìm `users` bằng `google_sub`; nếu chưa có, tạo Student với verified email/name/avatar và trường hồ sơ nullable. Nếu email đang thuộc user không có cùng `google_sub`, không liên kết và trả conflict. Nếu đã tồn tại theo sub, cập nhật tên/avatar; email chỉ cập nhật nếu không xung đột UNIQUE. Tạo auth session và phát refresh credential trong cùng transaction. Xử lý race qua UNIQUE; không mở transaction trong lúc gọi Google. |

### 5.2. Làm mới phiên — `POST /api/auth/refresh`

| Thuộc tính          | Hợp đồng đề xuất                                                                                                                                                                                                                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Quyền               | Không cần access JWT còn hạn; bắt buộc refresh cookie hợp lệ.                                                                                                                                                                                                                                                            |
| Request             | Không có body; browser gửi cookie theo same-origin. Yêu cầu Origin được allowlist và chống CSRF theo cấu hình thống nhất.                                                                                                                                                                                                |
| Thành công          | HTTP 200, trả `{ "accessToken": "…", "tokenType": "Bearer", "expiresIn": 900, "user": {…} }`; xoay refresh verifier và cập nhật cookie. Role/status đọc lại từ DB trước khi phát access token.                                                                                                                           |
| Lỗi                 | 401 `UNAUTHORIZED` với refresh thiếu/sai/hết hạn/đã revoke/reuse; 403 `ACCOUNT_DISABLED` hoặc `FORBIDDEN` nếu Origin không được phép; 503 `SERVICE_UNAVAILABLE`. Lỗi xác thực cookie phải xóa cookie phía client.                                                                                                        |
| Frontend            | Khi khởi động app hoặc access token hết hạn, thử refresh một lần; chỉ lặp lại request gốc sau refresh thành công. Không refresh vô hạn khi 401; chuyển về Guest và giữ return path nội bộ nếu hợp lệ.                                                                                                                    |
| Dữ liệu/transaction | Transaction khóa phiên hiện tại, xác minh hash, kiểm tra thời hạn/revocation, cập nhật verifier xoay vòng và trạng thái session. Nếu phát hiện token cũ bị dùng lại, revoke session theo chính sách đã duyệt. Đọc role/account status từ user trong transaction hoặc một snapshot nhất quán. Không gọi Google ở refresh. |

| Thuộc tính          | Hợp đồng đề xuất                                                                                                                                                                                                                                                                                            |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Quyền               | Cần `Authorization: Bearer <UniHub access token>` hợp lệ, account Active và session đang hoạt động.                                                                                                                                                                                                         |
| Request             | Không có body/query.                                                                                                                                                                                                                                                                                        |
| Thành công          | HTTP 200 `{ "user": {"id": 12, "email": "…", "fullName": "…", "avatarUrl": null, "role": "Student"} }` cùng `Cache-Control: no-store`. Chỉ trả thông tin tài khoản của chính người gọi; không trả `google_sub`, reviewer/admin internals hoặc refresh data. Hồ sơ học thuật đầy đủ thuộc API hồ sơ của TV2. |
| Lỗi                 | 401 `UNAUTHORIZED` nếu token/session không hợp lệ; 403 `ACCOUNT_DISABLED`; 503 `SERVICE_UNAVAILABLE`.                                                                                                                                                                                                       |
| Frontend            | Dùng response làm nguồn trạng thái UI hiện hành; role chỉ để điều hướng/ẩn mục, server vẫn kiểm tra quyền từng API. 401 xóa access token trong memory và quay về Guest; 403 hiển thị trạng thái không được phép.                                                                                            |
| Dữ liệu/transaction | Chỉ đọc user hiện hành và kiểm tra session; không ghi dữ liệu. Không cần transaction nhiều bản ghi.                                                                                                                                                                                                         |

### 5.4. Đăng xuất phiên hiện tại — `POST /api/auth/logout`

| Thuộc tính          | Hợp đồng đề xuất                                                                                                                                                                                                         |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Quyền               | Endpoint cookie-session; không yêu cầu access token còn hạn để vẫn đăng xuất được khi access hết hạn. Yêu cầu same-origin/Origin validation và CSRF guard.                                                               |
| Request             | Không có body; cookie refresh hiện hành.                                                                                                                                                                                 |
| Thành công          | HTTP 204, không body; revoke session nếu còn hợp lệ và luôn trả `Set-Cookie` xóa refresh cookie. Idempotent nếu cookie thiếu/hết hạn.                                                                                    |
| Lỗi                 | 403 `FORBIDDEN` nếu request CSRF/origin không đạt; 503 `SERVICE_UNAVAILABLE` nếu không thể đảm bảo revoke. Không trả 500 chi tiết.                                                                                       |
| Frontend            | Xóa access token và user state trong memory, sau đó điều hướng Guest. Nếu server lỗi mạng, vẫn xóa token trong browser nhưng báo người dùng rằng server-side logout chưa được xác nhận; không giả định cookie đã revoke. |
| Dữ liệu/transaction | Transaction đánh dấu session hiện tại revoked. Không xóa user/profile hoặc các phiên thiết bị khác. Không tạo API logout-all trong hợp đồng này.                                                                         |

Với session lookup bắt buộc ở middleware, access JWT cũ của session bị revoke bị từ chối ngay; token không thể được “thu hồi” bằng cách xóa ở browser nếu server không kiểm tra session. Nếu nhóm bỏ lookup này để dùng JWT stateless, access token bị đánh cắp vẫn dùng được tối đa tới `exp` (15 phút), dù refresh cookie đã bị xóa/revoke.

## 6. Middleware dùng chung

### `requireAuth`

Đặt tại `backend/src/middleware/` và dùng chung trên mọi module cần xác thực. Đề xuất kiểm tra:

1. Chỉ nhận `Authorization: Bearer`; không chấp nhận JWT từ query string, URL, body hoặc Google ID token trên API nghiệp vụ.
2. Xác minh JWT UniHub bằng allowlist thuật toán cố định, `iss`, `aud`, `exp`, `nbf` nếu có, `sub` là chuỗi ID `user_id` nội bộ, `sid` và `jti`. Không chấp nhận `alg=none`, thuật toán khác hoặc claims do client cung cấp ngoài token ký.
3. Đọc session active và user hiện tại từ Prisma; xác nhận role chỉ là Student/Admin và account status Active. Gắn một `authUser` đã kiểm chứng vào request context; không đưa raw token/Google claims vào log.
4. Thiếu/sai/hết hạn/revoked/session không còn/account không còn: HTTP 401 `UNAUTHORIZED`. Tài khoản Locked: HTTP 403 `ACCOUNT_DISABLED`. DB không truy cập: HTTP 503 `SERVICE_UNAVAILABLE`, không fallback thành Guest/Student.

### `requireRole('Admin')`

- Chỉ chạy sau `requireAuth`; dùng `authUser.role` vừa đọc từ DB, không decode riêng claim role hoặc tin header/body/query.
- Admin được phép đi tiếp; Student trả 403 `FORBIDDEN`. Guest đã bị `requireAuth` trả 401.
- Gắn middleware tại từng route Admin backend; route guard frontend không thay thế.
- Dùng cùng middleware cho API duyệt cơ hội TV1 và API Admin của TV2/TV3/TV4/TV5. Quyền Student-only/ownership vẫn do module tương ứng kiểm tra.

## 7. Cấu hình môi trường đề xuất

Tên dưới đây là dự kiến; không có giá trị bí mật nào được tạo hoặc ghi vào Git trong nhiệm vụ này.

| Tên                          | Nơi dùng / yêu cầu                                                                                                                                                                       |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `VITE_GOOGLE_CLIENT_ID`      | Frontend GIS; client ID là định danh công khai, không phải client secret.                                                                                                                |
| `GOOGLE_CLIENT_ID`           | Backend xác minh audience; phải cùng web client ID với GIS. Có thể cùng một giá trị nhưng cấu hình riêng theo workspace.                                                                 |
| `DATABASE_URL`               | Backend Prisma runtime; không gửi về frontend.                                                                                                                                           |
| `JWT_SIGNING_SECRET`         | Backend secret store; đề xuất entropy tối thiểu 256 bit cho HS256, không commit, không log; cố định thuật toán trong code/config validation.                                             |
| `JWT_ISSUER`, `JWT_AUDIENCE` | Backend JWT verifier/issuer; giá trị môi trường theo ứng dụng.                                                                                                                           |
| `AUTH_ALLOWED_ORIGINS`       | Backend allowlist origin chính xác để bảo vệ cookie endpoints; không wildcard.                                                                                                           |
| `BOOTSTRAP_ADMIN_GOOGLE_SUB` | Nếu nhóm chọn biến môi trường cho công cụ một lần: chỉ cấp tạm qua secret/config có kiểm soát; không đặt ở frontend hoặc Git. Có thể dùng input của lệnh provisioning thay cho biến này. |

Access TTL cố định tối đa 900 giây và refresh TTL tối đa 604800 giây; cấu hình không được phép vượt NFR. Không cần `GOOGLE_CLIENT_SECRET` cho luồng nhận ID token và verify trên server. HTTPS TLS 1.3 là yêu cầu NFR production; không đưa khóa/chứng thư thật vào repo.

## 8. Ranh giới dữ liệu và transaction

| Luồng                                     | Đọc/ghi                                                                          | Ranh giới                                                                                                                                                                                                                          |
| ----------------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Google login                              | Xác minh claims bên ngoài; đọc/ghi `users`; tạo/ghi `auth_sessions` theo đề xuất | Google call ngoài transaction; transaction DB ngắn, unique conflict an toàn.                                                                                                                                                       |
| Refresh                                   | Đọc/ghi session và đọc user role/status                                          | Một transaction bảo vệ rotation/reuse và quyền hiện hành.                                                                                                                                                                          |
| Me / middleware                           | Đọc user, role/status, session                                                   | Chỉ đọc; lỗi kết nối là lỗi dịch vụ.                                                                                                                                                                                               |
| Logout                                    | Đọc/ghi session hiện tại                                                         | Transaction revoke session; không sửa user.                                                                                                                                                                                        |
| Đổi role/khóa qua module quản trị sau này | Cập nhật users/status và `activity_logs`; khi khóa thì revoke các session active | Theo UC-14, thay đổi role và audit log phải cùng transaction; đề xuất role mới được đọc từ DB ở request kế tiếp, session tiếp tục ở role mới. Khi Locked, chặn request và thu hồi phiên ngay. Endpoint thuộc TV2, chưa triển khai. |

`users.role` CHECK của DB hiện giới hạn Student/Admin; CHECK không xác thực Google, không kiểm tra `sub`, không biểu diễn trạng thái khóa hoặc session. Database constraints và kiểm tra nghiệp vụ server là hai lớp riêng; backend vẫn phải xác minh claims, quyền, trạng thái, profile, ownership và transaction.

## 11. Tài liệu kỹ thuật đã kiểm tra

Ngày đối chiếu: **27/10/2026**. Không nâng Node/Express/Prisma đã chốt. Các phiên bản sau chỉ là **ứng viên để review**, chưa thêm dependency hay chốt lockfile:

- Google Identity Services: [Verify the Google ID token on your server](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token). URL tài liệu chính thức trả 403 từ proxy môi trường trong phiên này; vì vậy không khẳng định đã đọc được trang web. Đã đối chiếu gói phát hành chính thức [`google-auth-library@11.3.1`](https://github.com/googleapis/google-auth-library-nodejs): `verifyIdToken` nhận `idToken`/`audience`, source kiểm tra chứng thư/audience và token payload ghi `sub` là định danh unique không đổi theo email. npm registry metadata cho gói này có `engines.node >=22`, tương thích Node 24 đã chốt. Cần review lại exact version khi triển khai.
- JWT library đề xuất: [`jose`](https://github.com/panva/jose), phiên bản registry `6.2.13` (ESM; package README liệt kê Node.js). Tài liệu API [`jwtVerify` ở đúng tag](https://github.com/panva/jose/blob/v6.2.13/docs/jwt/verify/functions/jwtVerify.md) mô tả xác minh chữ ký và JWT claims, gồm issuer/audience. Đã chạy smoke test độc lập với tarball đúng phiên bản trên Node 24.19.0 (HS256 sign/verify thành công); không thêm dependency vào repository. HS256 vẫn phải được khóa bởi verifier allowlist, không suy ra chỉ từ việc thư viện hỗ trợ thuật toán.
- Session/cookie/CSRF: [OWASP Session Management Cheat Sheet](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/Session_Management_Cheat_Sheet.md) và [OWASP CSRF Prevention Cheat Sheet](https://github.com/OWASP/CheatSheetSeries/blob/master/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.md). Đã đối chiếu khuyến nghị Secure cookie/HTTPS, session state server-side, verifier/hash cho session token, kiểm tra Origin/Fetch Metadata và không coi SameSite là thay thế duy nhất cho CSRF defense.
- Phiên bản Node của dự án vẫn là Node 24 LTS theo [technology-stack.md](technology-stack.md); xác minh package trên không yêu cầu thay phiên bản đó.
